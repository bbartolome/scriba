## 1. Approach

- **Composition root first.** Take over `apps/web`'s generated root from #16 at `phase:core`. Each feature is one route-table entry with `loadChildren` and `data`. Nav and the gate read that `data`.
- **Device class gates navigation.** A root signal from CDK `Handset`, `Tablet` and `Web`, and a `canMatch` guard per entry. A phone never fetches a tablet feature's chunk.
- **Thin wrappers.** Typed API client (HttpClient, Zod, one typed error). One SSE client (one `EventSource`, demultiplexed by `module`, reconcile ticks). Shared components take Shell-local inputs and import no feature code. The editor wraps CodeMirror 6 and saves through #20's file API.

## 3. Phase plan

Phases are serial. Each is blocked by Platform `phase:scaffold`. Spec names are verbatim. The shared-components ticket split (card, diff, preview) is [proposed]. The card is ticket 1 because #23 `phase:file-tools-chat` waits on it. Criteria A1 to A10 follow the spec's checkbox order. First tests are proposals.

**`phase:core` (M1).** Gate for every feature UI phase. Publishes no contract slice.
- Scope: root route table and route-table entry pattern (`data`: nav label, Material icon, nav order, minimum device class `phone | tablet | desktop` with default `tablet`, scope app-level or project-scoped); landing (version, health) and not-found pages; dev proxy; typed API client (Zod, base error shape, `401` to `/setup`); SSE client (connection-state signal, demux, reconnect, reconcile tick); active-project signal; Material theming; nav; breakpoint gate; notices service and "server unreachable" banner; fake API client and fake event source.
- Acceptance:
  - A1 `npm run dev`: through the proxy, `/healthz` answers and an `EventSource` on the events route gets a Platform test event with no buffering delay.
  - A2 A dummy feature with one entry is its own chunk, shows its label and icon in nav, and is absent from the initial bundle.
  - A3 Minimum class `tablet` hides the view from the phone nav. Its URL on a phone shows the "larger screen" page. Resizing an open view below its class keeps it open and shows a notice.
  - A4 Phone shows the bottom nav, tablet the rail, desktop the side nav.
  - A5 A valid response gives parsed data. A Platform error body gives a typed error (status, code, message). A schema mismatch fails. A `401` navigates to `/setup`.
  - A6 Module A's envelope events reach only A's subscribers. Unknown modules and types are ignored without error.
  - A7 A simulated drop then re-open, `visibilitychange` to visible, `online`, and `pageshow` each emit one reconcile tick. A `CLOSED` stream is recreated with backoff.
  - A8 Light and dark follow the OS. The override persists across reloads on the device.
  - A9 A feature route test with the fake API client and fake event source runs under Vitest and serves as the template.
  - A10 The Platform Playwright e2e still passes. Its first step loads the Shell.
- Demo (six steps, spec): run dev; check landing version and health; toggle dark and reload; a phone viewport shows the bottom nav, hides the canvas entry, and shows "larger screen" at the canvas URL; stop the API to see the reconnecting indicator, then the banner; restart it and see one reconcile tick.
- First test: a `module: A` envelope reaches only A's subscriber, using a stubbed global `EventSource`.

**`phase:shared-components` (M1 card; M3 diff and preview).** Blocked by `phase:core`.
- Scope: tool-call card and view model (collapsed on phone, sources list); read-only diff on `@codemirror/merge`, unified or side by side by device class; Markdown preview on `ngx-markdown`, front matter hidden, sanitised.
- Acceptance:
  - A1 The card renders each status (`pending`, `running`, `done`, `error`) with tool name, arguments, output or error, and source paths. It is collapsed on a phone viewport and expands on tap.
  - A2 The diff shows insertions, deletions and changed lines. It is unified on phone and side by side on tablet and desktop, with a toggle override.
  - A3 Whitespace-only, LF-to-CRLF and front-matter-only changes show as changes. Identical inputs show "no changes".
  - A4 The preview shows a draft without its front-matter block. A `<script>` or inline event handler is neither executed nor rendered.
  - A5 The Agent loop's chat route can render an agent run's tool calls with the card, using only documented inputs (checked with the fake event source).
- First test: the card renders each status from a view model and starts collapsed at phone width. C2 must close before the M1 gate.

**`phase:editor` (M3).** Blocked by `phase:shared-components` and by #20 `phase:contract` (file reference type, file-API read and write requests).
- Scope: CodeMirror 6 Markdown editor with lossless load and save; line-separator detection; debounced and explicit save through the file API; save and conflict states; unsaved-changes guard and `beforeunload`; split view on tablet and desktop, edit/preview toggle on phones; tablet touch checks; editable merge view.
- Acceptance:
  - A1 Load then save with no edits sends a write byte-identical to the loaded content. Fixtures: YAML front matter, `_emphasis_` and `*emphasis*`, CRLF, mixed endings, no trailing newline, leading BOM, trailing whitespace.
  - A2 An edit changes only its range. All other bytes match.
  - A3 Typing then pausing (about 1.5 s idle) saves once. Cmd/Ctrl-S and the button save at once. Saves during an in-flight save coalesce into one follow-up save. Blur and route leave also save.
  - A4 State moves `unsaved → saving → saved`. A failed write shows `failed` and keeps the text. A precondition failure shows `conflict` and does not overwrite.
  - A5 Leaving the route or closing the tab with unsaved text prompts first.
  - A6 Tablet and desktop show the split view with a live preview. Phones show the edit/preview toggle.
  - A7 Tablet with touch emulation: tap to place the cursor, select by touch, type with the on-screen keyboard, and save, with no hardware key.
  - A8 The merge view's proposed side is editable and emits the edited text. Read-only mode is unchanged.
- First test: the round-trip fixture through the fake file API, mixed-endings fixture first, red before green. Blocked on the C7 spike result.

**`phase:polish` (M7).** Blocked by `phase:editor`.
- Scope: manifest, icons and service worker (app-shell assets only), excluding `/api`, `/healthz`, the events route and `/setup`; reload prompt after a server update; about panel (version from Platform version info, health from `/healthz`); accessibility pass; desktop keyboard shortcuts; loading skeletons; Shell empty states.
- Acceptance:
  - A1 Installable over the tailnet HTTPS URL and on loopback. Opens full screen.
  - A2 With the service worker active, nothing from `/api`, `/healthz`, the events route or `/setup` is served from cache. Streaming works after install.
  - A3 After a server update, the installed app prompts a reload, then runs the new bundle.
  - A4 An automated a11y check of nav, landing, notices, editor, diff and card reports no serious violations in either theme.
  - A5 Platform's e2e gains a phone-viewport check: the bottom nav is shown and the review step works there.
- Demo (five steps, spec): install on iPad over the tailnet; draft and save; `git diff` shows only the typed paragraph; on the phone, accept a pending change from the installed app; airplane mode shows reconnecting, then current state.
- A1 to A3 need a production build (O2). The phone review step also needs #20 `phase:pending-review` and #23 `phase:pending-writes` (the Platform e2e "accept change" step).
- Events-route requests may carry `ngsw-bypass` [proposed]. Check the parameter name in `@angular/service-worker` first.
- First test: parse `ngsw-config.json` and assert `/api/**`, `/healthz`, `/events` and `/setup` are excluded from caching.

## 4. Contracts

**Produces.** No contract slice; `/shell` is empty (#16). The Shell provides Angular APIs, versioned with the app:
- Route-table entry pattern and route `data` (`phase:core`). Adds `navPath` [proposed, O3].
- Typed API client; SSE client with per-module stream, connection-state signal (`connecting | open | reconnecting | closed`) and reconcile tick; device-class signal and breakpoint gate; active-project signal (route param under `projects/:projectId/` for project-scoped features); notices service; fake API client and fake event source (`phase:core`).
- Tool-call card; read-only diff (inputs: path, base text, proposed text, optional conflict flag); Markdown preview (`phase:shared-components`).
- Markdown editor (inputs: file reference, read-only flag, save mode; outputs: dirty flag, save state `saved | saving | unsaved | failed | conflict`, errors); editable merge view, which emits edited text (`phase:editor`).

**Consumes.**
- `/platform`: SSE envelope `{module, type, data}`, events route constant, base error shape and error-code convention, `/healthz` response, version info. Gate: Platform `phase:scaffold`.
- `/project-store`: project-relative path, file reference, file-API read and write, including the write precondition and conflict result. Gate: #20 `phase:contract`, which blocks `phase:editor` only.
- Not consumed: `/agent-loop`, `/graph-runner`, `/setup-auth`, `/compile-export`. The `/setup` path is a Shell-local constant (O3). Features pass their own route constants to the clients, so the route-prefix decision (#16 §7 item 18) does not change the Shell.

**Fakes.** Core fakes are generic and typed from `/platform`. Features supply their own contract types. The file fake follows #20: read returns `{path, content, hash, mtime}` (plus optional `upgraded`); write takes `{path, content, baseHash?}` and fails with #20's write-conflict code on a stale base. Every request names a `projectId`.

**Stubs.** Before #20 `phase:contract`, a local file stub is spike-only. The merge view emits a string. Accept semantics belong to #20 (C4).

## 5. Test strategy

- **Unit (Vitest):** SSE demux, unknown-member tolerance, backoff and `CLOSED` recreate (stubbed global `EventSource`). Reconcile ticks on re-open, `visibilitychange`, `online` and `pageshow`. API client success, typed error and schema mismatch. Editor save state machine (fake timers for the debounce). Diff, preview and sanitisation fixtures.
- **Integration (Angular Vitest, rendered routes):** the composed Shell with a dummy feature registered through the real entry pattern, the fake API client and the fake event source. Covers nav per device class, `canMatch` outcomes, keep-open-on-resize, theme persistence, the card check (shared-components A5), and a `401` setting the URL to `/setup` with no placeholder page.
- **Breakpoint:** drive `matchMedia` and `BreakpointObserver` per device class. [proposed] Checks that need a real viewport can use Vitest browser mode, which #20 also uses.
- **Editor round trip (#9, the deciding test):** the byte-level fixture suite from editor A1, through the fake file API. Load, save with no edits, and assert the captured write payload equals the input byte for byte. A targeted edit must change only its range. Kept as a regression test.
- **Diff:** fixture pairs assert markers (whitespace, LF/CRLF, front matter) and the unified/side-by-side switch by device class.
- **Security:** preview fixtures with `<script>`, `onerror` and `javascript:` links. Nothing executes or renders as active HTML.
- **Auth and health:** the `CLOSED` recreate checks `/healthz` and [proposed] `GET /api/platform/version`, which #18's default-deny guard covers, so a `401` means no credential. Before #18 `phase:token-guard`, tests use the fake client.
- **E2E (Platform's one Playwright run on the dev stack, #7):** the first step loads the Shell (core A10); proxy and unbuffered SSE (core A1); nav on every run. The Shell requests two more steps: tablet touch (editor A7) and phone review (polish A5). Platform owns `e2e/`.
- **Production-build project (O2):** polish A1 to A4 against a built bundle, since `ng serve` does not register the service worker.
- **Build:** lazy chunk and initial bundle from the production build (core A2).
- **Layer per criterion:** core A1 and A10 e2e, A2 build, A3 to A9 unit or integration. Shared-components A1 to A4 unit or fixture, A5 integration. Editor A1 to A6 and A8 unit or integration, A7 e2e. Polish A1 to A4 production build, A5 e2e.

## 7. Open questions

**Owner stop points.** Each has a recommendation.
- **O1. Phone light edits (map #2 against #20).** #2's resolution gives phones "light edits". #20 opens the editor on desktop and tablet only. Recommend: #20 allows the editor on phones in toggle mode and gates only long-form views. The Shell's phone toggle (editor A6) stays. Owner amends #20.
- **O2. E2E target and PWA checks (#7 against #16's spec text).** #7 and the spec's Testing Decisions say one Playwright run on the dev server. #16's spec still names the built bundle, though #16's survey §5 and §7 item 4 now recommend the dev stack. Polish A1 to A4 need a production build, which one dev-server run cannot give. Recommend: one Platform run on the dev stack, and PWA checks in a separate production-build project, agreed as an exception to #7 and written into the spec. Owner decides; #16 aligns.
- **O3. `/setup` and `/settings` constants and entry shape.** #16 keeps route constants in each module's slice, so neither goes in `/platform`. Recommend: Shell-local constants, documented as fixed by #6, each with a parity test in Setup & auth. One entry at `path: ''` with `setup` and `settings` children; `data.navPath: '/settings'` [proposed, one added field]; `minClass: phone`, so a phone's `401` reaches `/setup`. #18 §7 item 9 records `/settings` as "confirmed by Shell". This survey has not given that confirmation, so the owner confirms.
- **O4. Theme precedence (spec against #18).** The spec says the default follows `prefers-color-scheme` and there is "no server-side preference". #18 stores `theme` in `settings.yaml` (its first test saves `theme` alone). Recommend: device override, then the app default from #18's preferences (read through its route constant), then `prefers-color-scheme`. Owner amends the spec's theming line.
- **O5. Reconcile coalescing.** Acceptance A7 wants one tick per event, but re-open and `visibilitychange` often fire together. Recommend: coalesce within a short window, with a test, and amend A7 to "one tick per burst". Owner decides.
- **O6. Editor host for #21 (#21 Q9).** #21 proposes its own CodeMirror 6 YAML instance, which would remove the #26 edge from `phase:editor` to its UI phases. Recommend: the Shell editor stays Markdown-only, #21 uses its own instance, and #26's row is corrected. Owner decides with #21.

**Cross-spec checks.** Confirm with the sibling owner. The Shell does not decide these alone.
- **C1. Dev Host and Origin (#18 Q1, Platform).** An earlier "settled" note is withdrawn. #18 still lists this as open before `token-guard`. Recommend: dev at `127.0.0.1:4200`; the proxy forwards `Host` and `Origin` unchanged; `SCRIBA_DEV_ORIGINS` admits the host:port pair; `SCRIBA_SETUP_URL_BASE` points the setup URL at the dev server. - **C2. Recommend: the typed error carries the `AUTH_*` code, and the Shell posts a notice with it. The Shell does not import #18's sign-in notice. The Shell decides, before #18 `phase:token-guard`.
- **C4. Merge-view accept semantics (#20 Q12).** Closed for the Shell. The spec says the Shell supports either form, and #20 recommends optional `content` on accept. No Shell change.
- **C5. Active-project mismatch (#20).** Recommend: the route param stays the signal. On a mismatch or `project.switched`, the Project store's route activates or redirects. The nav slot is an outlet the Project store fills, so the Shell consumes no project-list request. Confirm with #20.
- **C6. Project-scoped host (#19 Q16).** `projects/:projectId/` can host #19's project model panel with no Shell change. Confirm.

Read back with `state.sliceDoc()`, not `Text.toString()`, and run the fixtures. Bare `\n` and BOM may show as placeholders. Fallback: keep each line's terminator. Unverified until the spike.
