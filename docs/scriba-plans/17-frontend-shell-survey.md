# #17 Frontend shell & shared UI: implementation survey

Map decisions #1 to #15 checked; no Shell conflict in #10 to #15. Cross-spec checks: #16, #18, #20, #23, #26. No map decision overrides the spec's text. Two map-level calls: #2 overrides #20 on phone editing (Q5), and #7 overrides #16's harness line on the e2e target (Q6).

## 1. Approach

- **Composition root first.** Take over `apps/web`'s generated root from #16 at `phase:core`. Each feature is one route-table entry with `loadChildren` and `data`; nav and gate read that data (§Feature-registration pattern).
- **Device class gates navigation.** A root signal from CDK `Handset`, `Tablet` and `Web`, and a `canMatch` guard per entry, so a phone never fetches a tablet feature's chunk (§Breakpoint gate; #2).
- **Thin wrappers.** API client (HttpClient, Zod, one typed error). SSE client (one `EventSource` on `/events`, demultiplexed by `module`, with reconcile ticks). Shared components take Shell-local inputs; the editor wraps CodeMirror 6 over #20's file API (#9).

## 2. Files and modules

Relative to the scriba repo root. "Taken over" means generated by #16 and owned by the Shell from `phase:core`.

- `apps/web/src/app/app.config.ts`, `app.routes.ts`, `apps/web/proxy.conf.js`: taken over. The proxy forwards `Host` and `Origin` unchanged (#18).
- `apps/web/src/app/shell/`: new. Registry, device class, `canMatch` guard, active project, API, SSE, theme, nav with a project-picker outlet, notices, pages.
- `apps/web/src/app/shared/`: new. Card, diff, Markdown preview, Markdown editor.
- `apps/web/src/app/testing/`: new. Fake API client and fake event source. The file fake ships with `phase:editor`.
- `apps/web/ngsw-config.json`, manifest and icons: polish.
- Not created here: `packages/contracts/src/shell.ts` (Platform), root `package.json`, Playwright harness.

## 3. Phase plan

Phases are serial. The card is `shared-components` ticket 1, because #23 `phase:file-tools-chat` (M1) is gated on it (#26).

**phase:core (M1).** Composition root, route table, landing and not-found pages, dev proxy, API, SSE and device-class seams, nav, theme, notices, generic fakes.
- Done when: "`npm run dev` serves the Shell. Through the proxy, `/healthz` answers and an `EventSource` on the events route receives a Platform test event with no buffering delay" (acceptance 1). A build-level check shows the dummy feature in its own chunk (acceptance 2). The demo script must also run.
- First test: SSE demux with a stubbed global `EventSource`. A `module: A` envelope reaches only A's subscriber; an unknown module or type is ignored without throwing.

**phase:shared-components (M1 card, M3 diff and preview).**
- Ticket 1, tool-call card. Done when: each status (`pending`, `running`, `done`, `error`) renders; the card is "collapsed by default on a phone viewport and expands on tap" (acceptance 1); and an integration test registers a dummy feature whose route subscribes through the fake event source to a test module, maps its events onto the card's documented inputs and renders the card. #23 repeats that check on its real chat route. Confirm with #23 before the M1 gate: attempt number on errors, per-family bodies, write-preview diff.
- Ticket 2, diff. Done when: identical inputs show "no changes"; whitespace, LF-to-CRLF and front-matter-only changes show markers; the layout follows device class, with an override.
- Ticket 3, Markdown preview. Done when: front matter is hidden and `<script>` and `onerror` are not rendered.
- First test, ticket 1: the card renders each status from a view model and starts collapsed at phone width.

**phase:editor (M3).** Gated by #20 `phase:contract` (#26) and `phase:shared-components`.
- Done when: a no-edit save is "byte-identical to the loaded content" across the round-trip fixtures; a targeted edit changes only its range; saves fire on debounce, Cmd/Ctrl-S, button, blur and route leave; state moves `unsaved → saving → saved`, with `failed` and `conflict`; the split view shows on tablet and desktop, with a phone toggle; the unsaved prompt fires on route leave and tab close; the merge view's proposed side is editable.
- First test: round-trip fixture through the fake file API, starting with the mixed-endings fixture (Q1), written red first.

**phase:polish (M7).** Done when: "The app is installable ... over the tailnet HTTPS URL and on loopback, and opens full screen." The reload prompt, a11y check and phone review step also pass (Q6 project). The demo script must also run.
- Work: `/events` requests carry `ngsw-bypass`, because `EventSource` cannot set headers. The parameter name is unverified; check `@angular/service-worker` first. Streaming must still work after install.
- First test: parse `ngsw-config.json` and assert `/api/**`, `/healthz`, `/events` and `/setup` are excluded from caching.

## 4. Contracts

**Exposes** (names verbatim from §Contracts): route-table entry pattern and route `data`; typed API client; SSE client (per-module event stream, connection-state signal, reconcile tick); device-class signal and breakpoint gate; active-project signal; notices service; fake API client and fake event source. From `phase:shared-components`: tool-call card, read-only diff view, Markdown preview. From `phase:editor`: Markdown editor, editable merge view.

**Consumes.** `/platform` (SSE envelope, events route constant, base error shape, `/healthz` response, app version info), gated by Platform `phase:scaffold`. `/project-store` (path, file reference, file-API read and write), gated by #20 `phase:contract`, which blocks `phase:editor` only.

**Fakes.** Core fakes are generic, typed from `/platform`. The file fake follows #20: read returns `{path, content, hash, mtime}`; write takes `{path, content, baseHash?}` and fails with a write-conflict error on a stale base. Every request names a `projectId` (Q4).

**Stubs.** Before #20 `phase:contract`, a local file stub is spike-only. The merge view emits a string, and accept semantics belong to #20. The `/setup` path is a Shell-local constant (Q3).

## 5. Test strategy

- **Unit (Vitest).** SSE demux, backoff and the `CLOSED` path (stubbed `EventSource`). Reconcile ticks: one each after a drop and re-open, `visibilitychange` to visible, `online` and `pageshow`. API client success, typed error and schema mismatch. Editor save state machine. Diff, preview and sanitisation fixtures.
- **Auth and health.** `CLOSED` recreate checks `/healthz` and `GET /api/platform/version`, which is guarded (#16) so a `401` means no credential. Before #18 `phase:token-guard`, tests use the fake client.
- **Integration (Vitest rendered routes).** Composed Shell, a dummy feature via the real entry helper, fake API client and fake event source. Covers nav per device class, `canMatch` outcomes, keep-open-on-resize, theme, the card check in ticket 1, and a `401` setting the router URL to `/setup`, with no placeholder page.
- **E2E (Platform Playwright, one run, #7).** Runs through `npm run dev` and the Shell's proxy, so it covers core acceptance 1 (`/healthz`, unbuffered SSE). Also the first step loading the Shell, and the tablet touch check (Playwright touch emulation, #8's CDP synthesis). Polish adds the phone review step, which needs #20 `phase:pending-review`.
- **Production-build project (Q6 exception).** Installability, service-worker exclusions, streaming after install, reload prompt after a server update, and axe in both themes. `ng serve` does not register the service worker, so these need the built bundle.
- **Build-level.** Lazy chunk and initial bundle, from the production build.

**Acceptance coverage** (criterion: phase, layer):
- Targeted edit changes only its range; saves on blur and route leave: editor, unit and integration.
- Agent chat renders the card from documented inputs, via the fake event source: shared-components, integration.
- Theme follows the OS and persists the override; `401` sets `/setup`: core, integration.
- Reconcile ticks on re-open, `visibilitychange`, `online`, `pageshow`; `CLOSED` recreate: core, unit.
- Diff unified or side by side by device class, with toggle override: shared-components, integration.
- Tablet touch-emulation editor check: editor, e2e. Phone review step: polish, e2e.
- Reload prompt, axe in both themes, installability, service-worker exclusions, streaming after install: polish, production-build e2e.
- Lazy chunk and initial bundle: core, build.

## 7. Open questions

1. **CodeMirror line endings.** §Phases `phase:editor` assumes the facet keeps mixed endings. The CodeMirror docs I read say that with the facet set, "only that precise separator will be used", so mixed endings may normalise. **Spike first:** set the facet to the dominant separator, read back with `state.sliceDoc()` (not `Text.toString()`), and run the fixtures. Bare `\n` and BOM may render as placeholders. Fallback: keep each line's terminator. Unverified until the spike.
2. **Dev origin. Settled by #18 and #16.** The proxy forwards `Host` and `Origin` unchanged (#18). `SCRIBA_DEV_ORIGINS` admits the dev origin (#16); `SCRIBA_SETUP_URL_BASE` points the setup URL at the dev server (#18). **Recommend:** dev at `127.0.0.1:4200`, no proxy rewrite. Residual check: confirm the dev `Host` is admitted, since #16 covers Origin and Host checks but #18 says only "origins".
3. **`/setup` and theme-read constants.** #16 keeps route constants in each module's slice, so neither goes in `/platform` or is imported from `/setup-auth`. **Recommend:** Shell-local constants, documented as fixed by #6, each with a parity test in Setup & auth. Confirm `/settings` for #18. One entry serves both paths: `path: ''` with `setup` and `settings` children, `data.navPath: '/settings'` for the single nav item (one added field), and `minClass: phone`, so a phone's `401` reaches `/setup`, not the larger-screen page.
4. **Active project and nav slot. Tension with #5 and #20.** #5 and #20 keep one library-wide active project. The spec reads it from the route param, so two tabs can disagree, and saves then fail with "project not active". #20 also lists the Shell as a consumer of project list requests, which the spec's Consumes table omits. **Recommend:** the signal stays the route param; on a mismatch or `project.switched`, the Project store's route activates or redirects. The nav slot is an outlet the Project store fills with its own component, so the Shell consumes nothing new.
5. **Phone editing. #2 wins over #20.** #2 gives phones "light edits", and the spec ships a phone edit/preview toggle. #20 opens the editor on desktop and tablet only. **Recommend:** #20 allows the editor on phones in toggle mode and gates only long-form views.
6. **E2E target. #7 overrides #16's harness line.** #7 and the spec's §Testing both say one Playwright run against the dev server. #16's harness line ("serving the web bundle") differs, though its own e2e script says "against the dev server". **Recommend:** ask #16 to align with #7. Keep only the PWA checks as a separate production-build project, agreed with Platform as an exception to #7's one run.
7. **Reconcile coalescing.** Stream re-open and `visibilitychange` can fire together, but the spec wants one tick per event. **Recommend:** coalesce within a short window, with a test.
8. **Theme precedence.** The spec says "no server-side preference", but #18 stores a theme in `settings.yaml`. **Recommend:** device override, then the app default (via the Q3 constant), then `prefers-color-scheme`, and amend the spec's line.

## 8. Driver brief

Order: core, with reconcile-tick tests; the tool-call card, then diff and preview; the CodeMirror 6 editor, using #20's file API with `projectId`; polish. A phase is done when every acceptance criterion in its #17 section passes, plus the demo script for core and polish. Stop at each phase boundary. Before `phase:editor`, stop until #20 `phase:contract` has merged and the Q1 spike has a result. Before polish's runtime checks, stop until Q6 is agreed with Platform. Confirm the card's inputs with #23 before its M1 gate. Test through rendered routes with fakes, never private services. Keep the map decisions: one SSE stream per tab, GET for reads, POST for commands, and `Host` and `Origin` forwarded unchanged (#18). Use glossary terms only, and say "agent run", not Run. Stop on any open question a spike cannot settle.
