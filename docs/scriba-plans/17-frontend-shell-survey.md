# #17 Frontend shell & shared UI: implementation survey

Map decisions #1 to #15 checked; no Shell conflict in #10 to #15. Cross-spec checks: #16, #18, #20, #23, #26. No map decision overrides the spec's text, but #2 overrides #20 on phone editing (Q5).

## 1. Approach

- **Composition root and one seam first.** Take over `apps/web`'s generated root from #16 at `phase:core`. Each feature is one entry with `loadChildren` and `data`; nav and gate read the same data (§Feature-registration pattern).
- **Device class as a root signal, gate at navigation.** `BreakpointObserver` over CDK `Handset`, `Tablet` and `Web` feeds the signal. A `canMatch` guard per entry means a phone never fetches a tablet feature's chunk (§Breakpoint gate; #2).
- **Thin wrappers.** API client: HttpClient, Zod, one typed error. SSE client: one `EventSource` on `/events` (#16), demultiplexed by `module`, with reconcile ticks (§Typed API client, §SSE client).
- **Presentational components.** Card and diff take Shell-local inputs. The editor wraps CodeMirror 6 over #20's file API (§Shared components; #9).

## 3. Phase plan

Phases are serial. The card is `shared-components` ticket 1, because #23 `phase:file-tools-chat` (M1) is gated on it (#26).

**phase:core (M1).** Composition root, route table, landing and not-found pages, dev proxy, API, SSE and device-class seams, nav, theme, notices, generic fakes.
- Done when: "`npm run dev` serves the Shell. Through the proxy, `/healthz` answers and an `EventSource` on the events route receives a Platform test event with no buffering delay" (acceptance 1). A build-level check shows the dummy feature in its own chunk, absent from the initial bundle (acceptance 2). The demo script must also run.
- First test: SSE demux with a stubbed global `EventSource`. A `module: A` envelope reaches only A's subscriber, and an unknown module or type is ignored without throwing.

**phase:shared-components (M1 card, M3 diff and preview).**
- Ticket 1, tool-call card. Done when: each status (`pending`, `running`, `done`, `error`) renders; the card is "collapsed by default on a phone viewport and expands on tap" (acceptance 1); and an integration test registers a dummy feature whose route subscribes through the fake event source to a test module, maps its events onto the card's documented inputs and renders the card. #23 repeats that check on its real chat route. First test: a view model renders name, arguments, output or error, and sources. Confirm with #23 before the M1 gate: attempt number on errors, per-family bodies, write-preview diff.
- Ticket 2, diff. Done when: identical inputs show "no changes"; whitespace, LF-to-CRLF and front-matter-only changes show markers; the layout follows device class, with an override. First test: the whitespace and line-ending fixture pairs.
- Ticket 3, Markdown preview. Done when: front matter is hidden and `<script>` and `onerror` are not rendered. First test: the sanitisation fixtures.

**phase:editor (M3).** Gated by #20 `phase:contract` (#26) and `phase:shared-components`.
- Done when: a no-edit save is "byte-identical to the loaded content" across the round-trip fixtures; a targeted edit changes only its range; saves fire on debounce, Cmd/Ctrl-S, button, blur and route leave; state moves `unsaved → saving → saved`, with `failed` and `conflict`; the split view shows on tablet and desktop, with an edit/preview toggle on phone; the unsaved prompt fires on route leave and tab close; the merge view's proposed side is editable and emits the text.
- First test: round-trip fixture through the fake file API, starting with the mixed-endings fixture (Q1). Written red first.

**phase:polish (M7).** Done when: "The app is installable ... over the tailnet HTTPS URL and on loopback, and opens full screen." The demo script must also run.
- First test: parse `ngsw-config.json` and assert `/api/**`, `/healthz`, `/events` and `/setup` are excluded from caching.

## 4. Contracts

**Exposes** (names verbatim from §Contracts): route-table entry pattern and route `data`; typed API client; SSE client (per-module event stream, connection-state signal, reconcile tick); device-class signal and breakpoint gate; active-project signal; notices service; fake API client and fake event source. From `phase:shared-components`: tool-call card, read-only diff view, Markdown preview. From `phase:editor`: Markdown editor, editable merge view.

**Consumes.** `/platform` (SSE envelope, events route constant, base error shape, `/healthz` response, app version info), gated by Platform `phase:scaffold`. `/project-store` (path, file reference, file-API read and write), gated by #20 `phase:contract`, which blocks `phase:editor` only.

**Fakes.** Core fakes are generic, typed from `/platform`. The file fake follows #20: read returns `{path, content, hash, mtime}`; write takes `{path, content, baseHash?}` and fails with a write-conflict error on a stale base. Every request names a `projectId` from the active-project signal (Q4).

**Stubs.** Before #20 `phase:contract` lands, a local file stub is spike-only. The merge view emits a string; accept semantics belong to #20. The `/setup` path is a Shell-local constant (Q3).

## 5. Test strategy

- **Unit (Vitest).** SSE demux, backoff and the `CLOSED` path (stubbed `EventSource`). API client success, typed error and schema mismatch. Editor save state machine. Diff, preview and sanitisation fixtures.
- **Auth and health.** `CLOSED` recreate checks `/healthz` and `GET /api/platform/version`. Version info is guarded (#16), so a `401` means no credential. Before #18 `phase:token-guard`, nothing is guarded, so tests use the fake client.
- **Integration (Vitest rendered routes).** Composed Shell, a dummy feature via the real entry helper, fake API client and fake event source. Covers nav per device class, `canMatch` outcomes, keep-open-on-resize, theme, `401` to `/setup`, and the card check in ticket 1.
- **E2E (Platform Playwright, one run).** #16's harness boots the API serving the built bundle, and nothing in #16 says it goes through the Angular dev server or its proxy (Q6). Covered: first step loads the Shell, and the automated tablet touch check (Playwright touch emulation, as in #8). Polish adds the phone review-step check, which needs #20 `phase:pending-review`.
- **Build-level.** Lazy chunk and initial bundle. Service-worker and installability checks need a production build, because `ng serve` does not register the service worker.

**Acceptance coverage** (criterion: phase, layer):
- Targeted edit changes only its range: editor, unit. Saves on blur and route leave: editor, integration.
- Agent chat renders the card from documented inputs, via the fake event source: shared-components, integration.
- Theme follows the OS and persists the override: core, integration. `401` to `/setup`: core, integration.
- Diff unified or side by side by device class, with toggle override: shared-components, integration.
- Tablet touch-emulation editor check: editor, e2e. Phone review step: polish, e2e.
- `CLOSED` recreate checks `/healthz` and auth first: core, unit. Lazy chunk and initial bundle: core, build.

## 7. Open questions

1. **CodeMirror line endings.** §Phases `phase:editor` assumes the facet keeps mixed endings. The CodeMirror docs I read say that with the facet set, "only that precise separator will be used", so mixed endings may normalise. **Spike first, the cheaper path:** set the facet to the file's dominant separator, read back with `state.sliceDoc()` (not `Text.toString()`, which always joins with `\n`), and run the fixtures. A bare `\n` in a CRLF file stays in its line and may round-trip, though it may render as a placeholder, as may BOM. Fallback: keep each line's terminator and rebuild on save. Also confirm #20's `read` keeps the BOM. Unverified.
2. **Dev origin. Settled by #18 and #16.** The proxy forwards `Host` and `Origin` unchanged (#18, Dev mode). `SCRIBA_DEV_ORIGINS` admits the dev origin (#16). `SCRIBA_SETUP_URL_BASE` points the printed setup URL at the dev server (#18). **Recommend:** dev at `127.0.0.1:4200`, both variables set to that origin, no proxy rewrite. Residual check: #18 says "extra loopback origins" and #16 says Origin and Host checks, so confirm the dev `Host` is admitted too.
3. **Where the `/setup` and theme-read constants live.** #16 keeps route constants in each module's slice, so neither goes in `/platform` or is imported from `/setup-auth`. **Recommend:** Shell-local constants, documented as fixed by #6, each with a parity test in Setup & auth. Answering #18: confirm `/settings`. One entry serves both paths: `path: ''`, `loadChildren` returning `setup` and `settings` children, and `data.navPath: '/settings'` (one added field) for the single nav item. Set `minClass: phone`, since the default `tablet` would send a phone's `401` to the larger-screen page.
4. **Active project. Tension with #5 and #20.** #5 and #20 keep one library-wide active project, shown in the Shell's nav slot (#20). The spec reads the signal from the route param, so two tabs can disagree and saves fail with "project not active". **Recommend:** the signal stays the route param. On a mismatch, or on `project.switched`, the Project store's route activates or redirects. The Shell does not reconcile.
5. **Phone editing. #2 wins over #20.** #2 gives phones "light edits", and the spec ships a phone edit/preview toggle. #20 opens the editor on desktop and tablet only. **Recommend:** #20 allows the editor on phones in toggle mode and gates only long-form views. The draft route is `phone`.
6. **E2E target and PWA checks.** #16's harness serves the built bundle, while the spec says the e2e runs against the dev server, so the proxy criterion may go untested. **Recommend:** a Shell check that runs `npm run dev` for the proxy and unbuffered SSE, and a production-bundle Playwright project for PWA checks, both agreed with Platform.
7. **Reconcile coalescing.** Stream re-open and `visibilitychange` can fire together, but the spec wants one tick per event. **Recommend:** coalesce within a short window, with a test.
8. **Theme precedence.** The spec says the override is device-local, with "no server-side preference". #18 stores a theme in `settings.yaml`. **Recommend:** device override, then the app default (read via the Q3 constant), then `prefers-color-scheme`. Amend the spec's line to cover the app default.

## 8. Driver brief

Run with `/navigator:pair`. Build Scriba's frontend shell in `apps/web` (Angular 22, standalone, signals, zoneless, Material) per issue #17: a composition root and seam, plus shared components. Order: the tool-call card, then the read-only diff and Markdown preview, then the CodeMirror 6 editor, whose round trip uses #20's file API with `projectId`. A phase is done when every acceptance criterion in its #17 section passes; for `phase:core` and `phase:polish` the demo script also runs. Stop at each phase boundary. Before `phase:editor`, stop until #20 `phase:contract` has merged and the Q1 spike has a result. Before polish's runtime checks, stop until Q6 is agreed with Platform. Confirm the card's inputs with #23 before its M1 gate. Test through rendered routes with the fake client and fake event source, never private services. Keep the map decisions: one SSE stream per tab, GET for reads, POST for commands, and `Host` and `Origin` forwarded unchanged (#18). Use glossary terms only, such as Pending change and Recipe, and say "agent run", not Run. Stop and ask on any open question a spike cannot settle.
